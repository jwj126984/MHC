# ParseSignal 函数修复 - 产品需求文档

## 概述
- **Summary**: 修复 ParseSignal 函数在处理长度为1的信号时的解析错位问题，确保起始位输入正确对应到实际的位位置。
- **Purpose**: 解决当起始位输入为87时，实际解析的是起始位80的值的问题，确保信号解析的准确性。
- **Target Users**: 开发人员和系统维护人员，确保CAN信号解析的正确性。

## 背景 & 上下文
- 目前 ParseSignal 函数在处理 Motorola 格式（大端序）的信号时，对于长度为1的信号存在解析错位问题。
- 当输入起始位为87时，实际解析的是起始位80的值，导致信号值错误。
- 连续两个字节长度16的解析没问题，只有长度为1的信号解析有问题。
- 这个问题会影响所有使用 ParseSignal 函数解析长度为1的信号的场景。

## 功能需求
- **FR-1**: 修复 ParseSignal 函数在处理 Motorola 格式、长度为1的信号时的解析逻辑。
- **FR-2**: 确保修复后的函数能够正确解析起始位为任意值的长度为1的信号。
- **FR-3**: 保持函数对其他长度信号的解析逻辑不变，确保向后兼容。

## 非功能需求
- **NFR-1**: 修复后的函数性能不应有明显下降。
- **NFR-2**: 修复后的函数应保持代码清晰易读。

## 约束
- **技术**: 保持函数签名不变，确保现有调用代码无需修改。
- **依赖**: 无外部依赖，仅修改函数内部实现。

## 假设
- 信号解析使用的是 Motorola 格式（大端序）。
- 输入的起始位值是有效的，即在数据范围内。

## 验收标准

### AC-1: 长度为1的信号解析正确
- **Given**: 输入数据中第10个字节（索引10）的值为 0b10000000（128）
- **When**: 调用 ParseSignal(data, 87, 1, 1.0, 0.0)
- **Then**: 返回值应为 1.0（正确解析第10字节的第7位）
- **Verification**: `programmatic`

### AC-2: 其他长度信号解析保持不变
- **Given**: 输入数据中包含有效的多长度信号
- **When**: 调用 ParseSignal 解析不同长度的信号
- **Then**: 返回值应与修复前相同
- **Verification**: `programmatic`

### AC-3: 连续两个字节长度16的信号解析正常
- **Given**: 输入数据中包含连续两个字节的长度16信号
- **When**: 调用 ParseSignal 解析这些信号
- **Then**: 返回值应正确，与修复前相同
- **Verification**: `programmatic`

### AC-4: 代码修改最小化
- **Given**: 查看修改后的代码
- **When**: 分析代码变更
- **Then**: 只修改了与长度为1信号解析相关的逻辑，未影响其他功能
- **Verification**: `human-judgment`
